# StencilMultiFaceClickController 轴向问题分析

## 一、当前检测逻辑

```
toCamera = (相机位置 - pivot.position).normalized
normal   = pivot.up 或 pivot.forward（取决于配置）
dot      = Vector3.Dot(normal, toCamera)
可见条件 = dot >= threshold
```

- **dot ≈ 1**：法线朝向相机，面正对
- **dot ≈ 0**：法线侧向相机
- **dot ≈ -1**：法线背对相机

---

## 二、你遇到的现象

| 现象 | dot 值 | 含义 |
|------|--------|------|
| 可见却点不到 | -0.909 | 当前用的法线背对相机 |
| 可见却点不到 | 0.185 | 当前用的法线几乎侧向相机 |
| 正常可点 | 0.963 | 法线正对相机 |

说明：**可见时，我们检测的法线方向与真正朝向相机的面不一致**。

---

## 三、可能原因

### 1. 模型导入轴向不一致

- **Blender**：默认 Z 向上，导出时可能变成 Y 向上
- **Unity**：Y 向上，Z 向前
- 若模型在 Blender 中「顶面」是 +Z，导入后 `pivot.up` 可能对应的是模型里的「前」或「侧」，而不是你视觉上的顶面

### 2. Pivot 与 Mesh 的轴向不同

- `Pivot_立方体.002` 是 Transform，`pivot.up` 是 Transform 的局部 Y
- 若 Pivot 在建模时被旋转过，或父子层级导致局部轴向与网格法线不一致，就会出现「用错轴」的情况

### 3. 检测的面和 Stencil 显示的面不一致

- Stencil 显示的是：**真正朝向相机的那个面**
- 我们只检测了 `pivot.up` 或 `pivot.forward`
- 横向旋转时，朝向相机的可能是 `pivot.forward`、`pivot.right` 等，而不是 `pivot.up`

### 4. 法线方向相反

- 若 `dot = -0.909` 时物体已可见，说明**可见面的法线是 -normal**
- 即模型里「朝外」的法线在 Unity 里是 `-pivot.up`，需要取反

---

## 四、如何确认你的模型轴向

在 Unity 里选中 `Pivot_立方体.002`，看 Scene 视图中的 Gizmo：

- **绿箭头 (Y)**：`pivot.up`
- **蓝箭头 (Z)**：`pivot.forward`
- **红箭头 (X)**：`pivot.right`

把魔方转到「顶面正对相机」时，观察：

1. 绿箭头是否指向相机？→ 是则 `pivot.up` 正确
2. 绿箭头是否背对相机？→ 则应使用 `-pivot.up`
3. 蓝/红箭头指向相机？→ 应改用 `pivot.forward` 或 `pivot.right`

---

## 五、结论与建议

| 情况 | 处理方式 |
|------|----------|
| dot 为负时已可见 | 使用 `-normal`（勾选 facePivotsInvertNormal） |
| 横向旋转时可见但点不到 | 检测 6 个面，取 maxDot（勾选 facePivotsCheckAnyFace） |
| 模型轴向与 Unity 不同 | 在 Inspector 中手动选：up / forward / right 或它们的负方向 |

建议在 Scene 中实际旋转魔方，观察 Gizmo 与相机的关系，确定应使用哪个轴（及是否取反）。
